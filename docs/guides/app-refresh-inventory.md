# Application refresh inventory

Baseline: `79956c25f2b9571c92a3fc89542a4ee99a74795a` (`origin/main`, PRs #264 and #267 included). This is a source inventory, not a browser acceptance result. “Confirmed” means the cited code demonstrates the behavior; “candidate” means the loader/scope is identified but same-DOM refresh behavior still needs a targeted test or trace. The supplied HAR showed nine WhatsApp provider/connection read pairs, five current-tenant reads and seven realtime ticket requests over about 32 seconds, with no document reload. It proves redundant reads, not a global React remount.

## Baseline findings and measurement

- **Confirmed shared causes:** each `useCurrentTenant` instance independently reads `/v1/tenants/current` ([hook](../../apps/admin/src/features/tenants/use-current-tenant.ts)); `UserMenu` turns an account hint into both account and identity events ([user-menu.tsx](../../apps/admin/src/components/admin/user-menu.tsx)), and identity-change consumers include cache/workspace reset paths; `PersonalIntegrationsPage` passes CRM an inline services object, while CRM's read effect depends on that wrapper ([personal-integrations-page.tsx](../../apps/admin/src/features/personal-integrations/personal-integrations-page.tsx), [crm-connections-page.tsx](../../apps/admin/src/features/crm/crm-connections-page.tsx)).
- **Confirmed destructive background loading:** Personal Integrations, CRM, assistant configuration, virtual employees and account set blocking loading state during subsequent reads; Personal Integrations/CRM/assistant configuration/virtual employees replace loaded regions with skeletons, and account blocks its profile card. See the rows below. This is not evidence that every shell route remounts.
- **Known safeguards:** CRM and WhatsApp have tenant/request guards; assistant configuration defers reload while dirty/saving; tenant branding, Savia Request, My Day layout and Studio extension editors defer changes while dirty/busy. These are useful domain protections, not proof that clean background reads preserve DOM/focus.
- **Measurement still required:** controlled authenticated desktop and mobile-width traces for My Day → account → personal integrations → CRM → WhatsApp → Studio; compare document requests, API reads by sanitized path, realtime ticket/socket requests, React mount identity, selected panel, focus and scroll separately. Keep raw HARs out of Git. No target read-count or remount budget is declared passed here.

## Initial disposition counts

- 30 admin feature directories inventoried, plus the admin shell and PWA/deployment recovery boundary.
- 5 confirmed destructive refresh surfaces: account, assistant configuration, CRM, Personal Integrations and virtual employees. CRM additionally has the confirmed wrapper-dependency trigger.
- 3 confirmed shared trigger classes: duplicate current-tenant reads, account-to-identity event fan-out, and inline CRM services wrapper/effect dependency. The five-read HAR observation is not extrapolated into a unique consumer count.
- Guarded or retaining examples recorded: CRM stale-tenant/request guard; assistant-configuration dirty blocker; virtual-employee edit blocker; My Day layout blocker; branding/Savia Request/Studio editor blockers; notifications scoped invalidation; Companion/mobile source-level retention and generation guards.
- Remaining rows are audit candidates or explicit boundaries, not “compliant” by virtue of passing current feature tests. Controlled browser/device verification, background-state assertions and read/remount attribution remain pending as noted above.

## Verification protocol for later batches

For each migrated row, test loaded → pending refresh → successful update, transient error, retry and scope switch while an old request is pending. Assert same DOM/editor instance, draft/selection/focus preservation, scope-correct content and current action feedback. Add an explicit empty-success case. Distinguish initial skeleton from background status and authorization revocation. For realtime, separately test initial catch-up, 200 ms coalescing, one in-flight follow-up, genuine reconnect recovery, listener replacement and cancellation. For secret-bearing panels, assert no secret enters read-cache keys, status text, logs or recovered form state. The whole-app browser trace must report requests, ticket/socket replacement, mounts and document reloads as different counters.
