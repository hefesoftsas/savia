# Personal pages and connected issue links

Approved conversational direction: personal-first Notion-style pages and structured work in Savia, shared with existing team members. User requested implementation after accepting Nango as an existing external service.

## Product contract

- Native Pages destination in Work; private roots and nested pages. Readers/editors are explicitly shared within the owner's active tenant. Children inherit root sharing. Existing collection authorization remains independent. Administrators do not automatically acquire private page content.
- Plate MIT editor, paragraphs/headings/lists/basic marks, safe clickable links and optional Jira Cloud/Linear cards. Persist content through the backend, no new browser persistence. Cards load metadata with the viewing user's personal connection and do not persist private metadata into shared document JSON.
- Collection blocks reference existing domain/collection and filtered table or Kanban; record pages can be linked to a collection record without duplicating its properties. Render through existing authorized data APIs.
- Search accessible pages, autosave with version conflicts preserving draft, full document revisions and restore. Images/attachments stored server-side. Existing Mi día remains unchanged.
- Personal Jira Cloud and Linear providers reuse Nango OAuth/reconnect/proxy; previews only, no issue mutations. Plain HTTPS links remain usable on disconnection or forbidden previews.
- Existing visual tokens and components, keyboard-accessible actions, responsive reading canvas, English source and multilingual user-facing labels.

## Architecture

Pages use dedicated D1 tables and an authenticated /v1/pages surface, separate from collection-wide additive role grants. Page ownership and sharing are evaluated on each request against current active tenant membership; root sharing is inherited. A page stores a bounded Plate-compatible JSON document, plain-text search extraction, optional record binding, version and timestamps. No role or title metadata can be supplied as identity by the client.

Nango previews use a fixed provider API and parsed issue identity, never fetch a pasted arbitrary URL. Metadata is per-viewer, transient and uncached in shared page content. URL parsing disallows credentials and unexpected hosts/protocols. Jira site identity must match accessible resources.

## Initial exclusions

No simultaneous CRDT editing, inline comment threads, external guest sharing, issue writes or bulk remote synchronization. No automatic deployment or production migrations.
