# Pages and issue links implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development with the repository's bounded Luna delegation rules.

**Goal:** Implement personal pages with structured collection references and connected issue previews.
**Architecture:** Dedicated D1 pages and inherited root shares; Plate editor and current Savia APIs; Nango personal issue providers.
**Tech Stack:** React, Plate MIT, Hono OpenAPI, D1/R2, Nango.
**Spec:** docs/superpowers/specs/2026-10-01-pages.md

## Global constraints

English code/docs, existing UI tokens, no browser persistence, no issue writes, no production deployment. New dependencies MIT/Apache; Nango is an accepted existing external service.

## Review focus

- Cross-user and cross-tenant page access, including inherited sharing and revoked membership.
- Stale saves and restores preserve newer content and the user's draft.
- Pasted URLs never become arbitrary authenticated upstream fetches.
- Shared cards never reveal the author's remote metadata to another viewer.
- Navigation and rapid page switching never save a draft into a different page.

The importer rejects this mismatch before copying; no auth import behavior was changed in this work. The API integration test now supplies a stubbed local SMTP transport, which its user-creation flow requires.
